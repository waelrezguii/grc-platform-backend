# GRC Risk Management Backend — CLAUDE.md

## Project Overview

Spring Boot 4.0.3 / Java 17 backend for a **Governance, Risk & Compliance (GRC)** platform built for [Company]. Covers risk scenarios, assets, controls, compliance frameworks, audit campaigns, governance documents, threats, vulnerabilities, KRIs, and treatment plans.

- **Group / Artifact**: `com.[Company].riskmanagement` / `risk-management-be`
- **Frontend**: Angular app expected at `http://localhost:4200`
- **Database**: PostgreSQL, DB name `riskbdd`, port 5432
- **API docs**: Swagger UI at `/swagger-ui/index.html` (SpringDoc OpenAPI 3)

## Build & Run

```bash
# Build (skip tests)
./mvnw clean package -DskipTests

# Run
./mvnw spring-boot:run

# Run tests
./mvnw test
```

## Architecture

### Package Layout

```
com.[Company].riskmanagement
├── base/           # BaseEntity, AuditableEntity, SoftDeleteEntity
├── config/         # Spring configs (Security, CORS, JPA auditing, OpenAPI, WebClient)
├── constant/       # Enums for every status/type field
├── controller/     # REST controllers (one per domain)
├── dto/            # RequestDTO / ResponseDTO pairs + summary DTOs
├── exception/      # Custom exceptions + global handler
├── mapper/         # Manual mappers (entity ↔ DTO)
├── model/          # JPA entities + History entities
├── repository/     # Spring Data JPA repositories
├── scanner/        # CVE/NVD integration
├── scheduler/      # Spring @Scheduled tasks
├── security/       # JWT utils, auth filter, auth token
├── seed/           # DB seeders (admin, roles, reference data)
└── service/        # Business logic
```

### Base Entities

| Class | Adds |
|---|---|
| `BaseEntity` | UUID id, `createdAt`, `updatedAt` |
| `AuditableEntity extends BaseEntity` | `createdBy`, `updatedBy` (Spring Data auditing) |
| `SoftDeleteEntity extends AuditableEntity` | `deleted` flag + `deletedAt` |

All domain entities extend one of these — check which one before adding fields.

### Conventions

- **IDs** are `String` UUIDs generated by Hibernate (`GenerationType.UUID`).
- **DTOs** come in pairs: `*RequestDTO` (input) and `*ResponseDTO` (output). Summary variants (`*SummaryDTO`) exist for list/nested use.
- **Mappers** are plain classes with static or instance methods — no MapStruct.
- **Controllers** return `ResponseEntity<T>` and are annotated `@RequiredArgsConstructor`.
- **Delete endpoints** return `ResponseEntity<Map>` with `{ "code": "SUCCESS", "message": "..." }`.
- **Pagination**: list endpoints accept `page`, `size`, `sortBy`, `sortDir`, `archived` query params and return `Page<T>`.
- **History**: every major entity has a parallel `*History` entity and repository for audit trail. Services write a history record on every mutating operation.
- **Archive**: entities have an `archived` boolean; a dedicated `ArchiveRule` drives automatic archiving via `ArchiveScheduler`.
- **Soft delete**: use the `SoftDeleteEntity` base — do not hard-delete records in services.
- **Enums** live in `constant/`. Always use the existing enum type in entities and DTOs rather than raw strings.
- **i18n**: user-facing messages go through `messages.properties` (EN default) with `messages_ar.properties` and `messages_fr.properties`. Use `MessageSource` to resolve messages.

## Authentication & Security

- JWT tokens are signed with an **in-memory key** (regenerated on restart — all sessions invalidate on redeploy).
- Token expiry: **1 hour**.
- Sessions are persisted in `user_session` table (`UserSession` entity). The `JwtAuthFilter` validates both the token signature and the active session.
- Login security: max **5 attempts**, **15-minute lockout** (`LoginSecurityProperties`).
- MFA via OTP (`OtpService`, `/api/auth/mfa/validate`).
- Roles + permissions: `Role` has a set of `Permission`s; users can also have `extraPermissions`. Method-level security is enabled (`@EnableMethodSecurity`).
- Public endpoints: `/api/auth/**`, `/swagger-ui/**`, `/v3/api-docs/**`.

### JWT

`JwtUtils` is a Spring `@Component` — inject it, never call statically. The key is loaded from `jwt.secret` via `@PostConstruct` so it survives restarts and can be rotated without code changes.

- Unauthenticated requests return `401` with `{"code":"UNAUTHORIZED","message":"Authentication required"}`
- Public endpoints: `/api/auth/**`, `/swagger-ui/**`, `/v3/api-docs/**`

### Phase 3 — SpotBugs + Find Security Bugs (SAST) ✅ Complete

Runs via: `./mvnw compile spotbugs:check`

- Plugin: `spotbugs-maven-plugin` **4.9.3.0** (upgraded from 4.8.6.4 — required for JDK 24 / ASM 9.7 support)
- Find Security Bugs plugin: `findsecbugs-plugin` 1.13.0
- Effort: Max, Threshold: Low, `failOnError: true`
- Include filter: `spotbugs-security-include.xml` — scans SECURITY + CORRECTNESS categories only
- Exclude filter: `spotbugs-exclude.xml` — justified suppressions for false positives

**4 real vulnerabilities fixed:**

| File | Pattern | Fix |
|---|---|---|
| `GovernanceDocumentController.java` | `PATH_TRAVERSAL_IN` | Sanitize filename with `replaceAll("[^a-zA-Z0-9._-]", "_")` + `normalize()` + `startsWith(base)` containment check |
| `AuditService.java` | `UNSAFE_HASH_EQUALS` | Use `MessageDigest.isEqual()` for constant-time hash comparison (prevents timing attacks) |
| `QualysAdapter.java` | `XXE_DOCUMENT` | Disable DOCTYPE declarations and external entity expansion on `DocumentBuilderFactory` |
| `CveImportService.java` | `CRLF_INJECTION_LOGS` | Strip `\r\n` from user-controlled `keyword` and `cveId` before logging |

**Suppressions in `spotbugs-exclude.xml`** (all documented with justification):
- `SPRING_ENDPOINT` — every `@GetMapping`/`@PostMapping` is intentional; not exploitable
- `SPRING_CSRF_PROTECTION_DISABLED` — stateless JWT API; CSRF does not apply
- `IMPROPER_UNICODE` — false positives on standard string operations with no user-controlled Unicode paths
- `CRLF_INJECTION_LOGS` (Low confidence) — log statements using internal enum values or system-generated IDs
- `CRLF_INJECTION_LOGS` in `RiskReportService` — sanitized with `.replaceAll()` but FindSecBugs taint analysis does not recognize it as a sanitizer

## Adding a New Domain Entity (Checklist)

1. Create entity in `model/` extending the appropriate base class.
2. Create a `*History` entity if mutation tracking is needed.
3. Add repository interface in `repository/`.
4. Add `*RequestDTO` and `*ResponseDTO` (plus `*SummaryDTO` if nested).
5. Add mapper in `mapper/`.
6. Add enums to `constant/` if new status/type fields are introduced.
7. Implement service in `service/` — write history record on every mutation.
8. Add controller in `controller/` with standard pagination + archive params on list endpoint.
9. Add error codes to `ErrorCode` if new failure cases arise.
10. Add i18n keys to all three `messages*.properties` files.
